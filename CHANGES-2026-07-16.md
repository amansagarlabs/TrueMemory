# Session Changes Log

## 1. Dark Theme CSS Override Fix

**File:** `app/globals.css`

**Problem:** Dark theme background overrides using `[class*="bg-[#fff"]` (substring match) were matching `hover:bg-[#fff5a5]` inside the raw class string. This caused `background-color: rgba(255,255,255,0.035) !important` to fire on buttons with yellow backgrounds, killing their fill color.

**Root cause:** CSS attribute selector `*=` does substring matching on the entire class attribute. `hover:bg-[#fff5a5]` contains the substring `bg-[#fff`, so the override selector matched even though the element's actual base background was `bg-[#f6e879]`.

**Fix:** Changed all `bg-` and `border-` dark override selectors from `[class*="..."]` (substring) to `[class~="..."]` (exact token match). Tailwind classes are space-separated tokens, so `~=` matches only when the class is a standalone token. `hover:bg-[#fff5a5]` is a different token than `bg-[#fff5f0]` and won't match.

**Affected selectors:**
- `.dark main [class~="bg-white"]`
- `.dark main [class~="bg-[#fff5f0]"]`
- `.dark main [class~="bg-[#fff0e8]"]`
- `.dark main [class~="bg-[#f5f5f5]"]`
- `.dark main [class~="bg-[#f1e8dc]"]`
- `.dark main [class~="bg-[#e5e7eb]"]`
- `.dark main [class~="border-*"]` (all border overrides)
- Same selectors under `.dark main.homepage-shell`

**Why this is future-proof:** `~=` will never match variant-prefixed classes (`hover:`, `focus:`, `active:`, etc.) because they're different tokens. Any future button with `hover:bg-[#fff5a5]` or similar will work correctly.

## 2. Pricing FAQ Rewrite

**File:** `app/pricing/page.tsx`

**Problem:** FAQ used `<details>/<summary>` HTML elements with a CSS-only cross icon (two overlapping spans rotated). No clear open/closed visual indicator. Tight spacing (`space-y-1`).

**Fix:**
- Replaced with custom `FaqItem` component using `useState` for toggle
- Lucide `Plus`/`Minus` icons for open/closed states
- `space-y-3` for proper spacing between items
- `py-5` padding for better touch targets
- Added `import { useState }` and `Plus, Minus` from lucide-react

**Why:** `<details>/<summary>` has inconsistent styling across browsers and limited control over animations. Custom component gives full control over icons, spacing, and transitions.

## 3. Reusable Site Footer Component

**File:** `components/ui/site-footer.tsx` (new)

**Problem:** Homepage had a full-featured footer (~100 lines) with PaperDither background, 4-column grid, and wordmark. Every other page either had no footer or a different one.

**Solution:** Extracted into a standalone `SiteFooter` component with:
- `BrandMark` sub-component (orange grid logo)
- PaperDither background (simplex shape, dark/light variants)
- 4-column grid: Brand + pills + CTA | Product links | Build links | Agent layer features
- Bottom bar: copyright, system status dot, open source badge
- "KONTEXT" wordmark with `footer-dither-wordmark` CSS class

**Why reusability:** DRY principle. One source of truth for footer content. Changes propagate to all pages automatically.
