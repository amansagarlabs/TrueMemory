# TrueBot deployment runbook

TrueBot lives in the existing Next.js app at `/truebot` and in the existing FastAPI/Supabase PostgreSQL stack at `/api/truebot`. The feature defaults to **off**. Provider keys belong only in Render server environment variables. Browser clients use existing user sessions. TrueBot API rejects scoped API tokens until a delegated workspace/agent contract exists.

As checked on **2026-10-14**, the connected production Supabase project has none of the three TrueBot tables, so this release is **not ready for production activation**. The code can deploy with the feature disabled while the database and worker are prepared. No live migration, provider call, or worker creation was performed during implementation.

## Release order

1. Run `backend/db/init/022_truebot.sql` against the existing Supabase PostgreSQL database with the migration role. This migration is additive and idempotent. Confirm `truebot_agents`, `truebot_runs`, and `truebot_worker_heartbeat` exist. Do not expose these tables through Supabase browser roles; only the server database role needs access.
2. Configure the existing Render API service with `OPENAI_API_KEY`, `TRUEBOT_OPENAI_MODELS` (a comma-separated allowlist of actual models accessible to the account), `TRUEBOT_ENABLED=true`, and existing `DATABASE_URL`. Keep the existing `AMAN_JWT_SECRET`, CORS and secure cookie settings. Optional limits: `TRUEBOT_MAX_AGENTS=10`, `TRUEBOT_DAILY_RUNS=50`, `TRUEBOT_CONCURRENT_RUNS=2`. Confirm the allowlisted models support the Responses API and function calling before enabling tools. Do not place `OPENAI_API_KEY` in any `NEXT_PUBLIC_*` variable.
3. Deploy a continuously running **Render background worker** from the same repository, branch and `backend` root/Dockerfile as the API. Override its Docker command to `python -m worker.truebot_worker`. Give it the same `DATABASE_URL`, `OPENAI_API_KEY`, `TRUEBOT_OPENAI_MODELS`, and `TRUEBOT_ENABLED=true`. Worker and API must share the same database and provider configuration. Start one worker initially. A Free web service alone does not process TrueBot jobs. Render documents background workers as continuously running services; review the plan cost before creating one. [Render background workers](https://render.com/docs/background-workers), [Render Blueprint service types](https://render.com/docs/blueprint-spec).
4. Deploy the existing Vercel frontend with `NEXT_PUBLIC_API_URL` pointing at the Render API and verify that the production frontend origin is in Render's `CORS_ORIGINS`. Vercel production environment changes take effect in the next production deployment. [Vercel environment variables](https://vercel.com/docs/environment-variables).
5. Sign in with a disposable test user at `/truebot`. Check `/api/truebot/config` reports `enabled: true`, the OpenAI provider is configured, and `worker_ready: true`. Create an agent with no memory, explicitly approve provider processing at run submission, and verify a real task reaches `completed` with nonempty output and usage. Refresh to confirm agent/run history. Test cancellation and a second user receiving 404 for the first user's agent/run IDs. Then test memory search and save in a disposable workspace with the separate per-run approvals. Verify the worker and API use the same database, and inspect worker health after a restart.

## Operational behavior

The worker claims queued rows with `FOR UPDATE SKIP LOCKED`; the API never runs a model call in its request lifetime. A heartbeat gates new submissions when the worker is offline. Queued jobs older than 15 minutes and interrupted running jobs with expired leases become failed. A task is **not replayed** automatically after an ambiguous provider call or memory write; submit a new task to retry. The user may cancel a queued/running task, but a provider request or memory write already in progress can finish before cancellation takes effect. Runs have a 15–120 second deadline and per-agent model/tool-call limits. Progress is available through `/runs/{id}` and the authenticated `/runs/{id}/events` stream.

Only OpenAI's model API is executable in this release. Anthropic, xAI, local inference, autonomous coding runtimes, automations, and personal provider credentials are visible as unavailable capabilities. No terminal, browser, arbitrary HTTP, or computer-use tool is exposed. OpenAI calls use the official Responses API with `store: false`; stateless function-call continuation carries the prior response items. [OpenAI Responses migration](https://developers.openai.com/api/docs/guides/migrate-to-responses), [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling).

## Rollback

Set `TRUEBOT_ENABLED=false` on the Render API and worker. The existing TrueMemory routes remain available; retain the additive tables so run and agent history can be recovered. Do not drop tables containing user data as part of a routine rollback.
