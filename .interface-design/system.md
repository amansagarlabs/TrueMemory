# TrueMemory public docs system

## Direction

Editorial documentation for humans and agents: precise, quiet, technical, and evidence-led. Public pages use a paper-white canvas with blue infrastructure accents; dark mode is reserved for dense developer reference surfaces.

## Signature

Every core story follows the memory loop: remember → search → retrieve. Use it as a visible flow in product pages, docs quickstarts, and technical articles.

## Palette

- Canvas: `#f8fafc`
- Ink: `#111827`
- Secondary text: `#64748b`
- Quiet border: `#dbe3ee`
- Infrastructure blue: `#1769e0`
- Memory highlight: `#f6e879`
- Dark reference canvas: `#080807`

## Layout and components

- Shared public shell with compact top navigation, clear action, and blue multi-column footer.
- Editorial hero with short eyebrow, tight display headline, one paragraph, and one primary action.
- Product pages use large whitespace, thin borders, and structured three-step flows instead of generic metric cards.
- Blog articles use a narrow reading column, metadata rail, abstract hero panel, callout blocks, and related-note navigation.
- Docs pages use dark dense reference surfaces, persistent section navigation, stable anchors, and copyable code blocks.

## Depth and spacing

Use borders and surface shifts as the primary depth strategy; avoid dramatic shadows. Base spacing is 4px, with 12px control gaps, 24px card padding, and 80–144px section separation.

## Content rules

Only claim behavior supported by repository implementation or explicit test evidence. Mark history, future proposals, and unverified founder narratives separately.
